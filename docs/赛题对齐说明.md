|------|------|------|----------|

## 2.9 我们**真机跑过**，并修掉了这些问题

用 `deepseek-V4.1-flash` / `deepseek-v4-pro` 加真实数据源跑通整条流水线，实测到并修复：

| 现象 | 根因 | 现在的行为 |
|------|------|------------|
| `python -c "import paths, llm; llm.check_models()"` 说没配 key | `.env` 只在 `web/app.py`/`cli/Agent.py` 里加载 | `env_boot.load_project_env()` 统一加载，任何入口都读得到 |
| 回答里冒出一大段推理内容 | 推理模型把思考写在 `reasoning_content`；前端误当正文渲染 | 只把 `content` 当正文；`reasoning_content` 只用来推「模型正在思考…」 |
| 流式收不到字 | `ChatOpenAI` 默认不开流式 | 显式 `streaming=True`；DeepSeek 的 flash / pro 都支持流式 |
| 假设/审稿跑很久仍降级 | `HYPOTHESIS_PROMPT` 的 JSON schema 没进提示词；pro 的推理吃满 `max_tokens` | 契约+技能一起送；重试改成"换成 flash + 抬额度"（稳定出 JSON）|
| 审稿人反复判"缺检验" | 设计步骤只能声明"做什么检验"，参数是空数组 | 新增数据绑定层：用文献字段真的构造分组（是否报告数据集 / GNN vs 非 GNN / 年份切分 / 方法关键词）后再检验 |
| 假设总被否 | 没有实验数据却提"mIoU 更高" | 把「文献字段可得性」的真计数交给模型，并硬约束"数值不足 6 篇不得提数值比较假设" |

**耗时**：与账号额度、网络、文献数量强相关（一次工作流要 8-12 次模型调用）。
`tests/live_run.py` 可在真实 key 下量出你这台机器的单轮耗时。
**判 `reject` 的含义**：假设被证据否定（负结果），不是流程失败 —— 报告里就是这么写的。

## 4. 我们**没有**做到 / 明确降级的（不做粉饰）

1. **中文核心期刊覆盖**不如知网/万方。知网不开放个人 API，万方需商务授权；
   当前中文源是 OpenAlex(`language:zh`) + Crossref，不少中文文献没有摘要或 DOI。
2. **"实验"是仿真/复现实验，不是湿实验**。用户不给数据时，"算"退化为文献计量统计
   （被引分布、年份-被引相关、新旧 Mann-Whitney）—— 是真数值，但意义不同，
   报告里会标"文献计量"来源，不会冒充实测。
3. **`deepseek-v4-pro` 推理阶段首字慢**（十几秒量级）。已按任务分层用 flash + 前端推
   "模型正在思考…"，但深度推理的等待无法消除。
4. **DeepSeek 按账号动态限流**（没有公开固定 RPM）。已做令牌桶与规划缓存；
   多用户并发时仍会排队，可用 `DEEPSEEK_RPM` 按实际额度调整。
5. **MCP 只实现 tools 能力**，`resources/list` / `prompts/list` 返回空列表（当前需求用不上）。
6. **"证据是否充分"仍依赖模型判断**（审稿人角色）。代码只能机械化校验
   （数值一致、编号越界、判据缺失、参数缺失）；这类判断没有公开基准可对齐。
7. **迭代最多 1 轮（默认）**。两轮都不收敛的题，第三轮基本也不会收敛，所以选择
   如实报"未收敛"并给出返工项，而不是无限重试烧额度。

---

## 5. 一句话总结

> 我们把"AI 做科研"拆成了**九步可执行、可中断、可复核的流水线**：
> 每一步的产物都带证据链（文献编号 / 工具参数 / 复算结果），
> 验证步骤会**真的把计算重跑一遍**，不一致就判返工 ——
> 这样报告里的每个数字都能追到出处，而不只是"模型说它对"。
